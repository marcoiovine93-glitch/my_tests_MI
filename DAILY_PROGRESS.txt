    - Difference between end host data and end data at the end of an acc region:
        - end host data : it simply ends the temporary mapping from host variables to the corresponding device pointers (the device pointers are not 
          exposed anymore)
        - end data : the !$acc data manages the time for which the data on the GPU exists!!!! --> so end data copy back the variables declared

        - THE DIFFERENCE DEPENDS ESSENTIALLY BY THE FACT THAT "data" STANDS FOR A STRUCTURED DATA REGION, IN WHICH DATA IS AUTOMATICALLY
          COPIED BACK FROM DEVICE TO HOST AND THE DEVICE VARIABLE ARE DEALLOCATED!!!
        - So instead of run many copyin, one for each variable to be copied on the device, we can create a unique structured data region 
          specifying at the beginning the host variables to be copied to the device or created and inside it define the host_data
          to introduce the mapping from host variables to the corresponding device pointers!!
        - But Warning!!!: to run the commands on openACC : update host() and exit data delete(), we can simply run: exit data copyout --> it does both the things in one!!!

                                                    - cublasZgemmStridedBatched : the matrices are passed in a contiguous block of memory

                                                    - transa in the cuBLAS API tells the routine what form of matrix A to use: unchanged,

                                                - GENERAL CONCEPT:
                                                    - The stride, defined also for cuSOLVER for diagonalization LAPACK as leading dimension, 
                                                      represents the jump in memory needed to pass from a matrix to the next one, when accessing
                                                      a contiguous block of memory storing all the matrices;
                                                    - in the case of LAPACK, probably it takes into account only the the leading dimension!
                                                        - WHY??? : because probably it has to know what is the current column!!! 
                                                    - in cuSolver, essentially we define the leading dimension like a stride an its purpose
                                                      is to access the data in the proper way: ho much I need to slice/jump in memory to get
                                                      the next array/matrix? --> this is different from the computation, that is still performed
                                                      on a square matrix of dimension n x n (in our case, nbase x nbase)
                                                    - in cublas, the concept is similar:
                                                        - we define the rows and columns of the input and output matrices
                                                        - but at the same time we define for each of them a leading dimension and also a stride
                                                        - in this case the stride is not the number of rows, but is the number of elements
                                                          between one matrix and the next one
                                                        - it is probably defined because the leading dim. is not sufficient (we don't have 
                                                          necessarily square matrices)
                                                        - in general, the concept od stride, or leading dimension, is defined to take into 
                                                          account how data is stored in memory to take into account the fact that the computation
                                                          should not be done necessarily on the whole array given!!!
